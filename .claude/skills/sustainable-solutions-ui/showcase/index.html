Design skill, rendered output

What the Sustainable Solutions UI skill produces

Every element on this page is drawn with the design tokens, page skeleton, component states and attribution rules defined in the sustainable-solutions-ui skill. Nothing here is decoration chosen by hand: the colours, type steps, spacing, dark mode and focus rings come straight from the token file that was extracted from the live lab site.

Skill
sustainable-solutions-ui, version 2.1.0
Target stack
Astro, Tailwind CSS v4, Vercel
Tokens verified
9 November 2026, from live site source
Data on this page
Synthetic

All numbers, place names, papers and DOIs on this page are invented for demonstration. They must not be read as lab results. The purpose is to show form, states and structure, not findings.

Dark mode is part of the system, not an afterthought. The toggle writes data-theme on the html element and remembers the choice in localStorage('ssl-theme'), which is how the production site does it.

Ten steps, 1.20 minor third, anchored at 16px. Serif for headings, Inter for interface text, monospaced only for code.

Four pixel base. Layout widths 1200px container and 680px prose measure, so long explanations stay readable next to a wide map.

Motion: 120ms for controls, 200ms for interface, 400ms for content, one shared easing curve, and every transition disabled under prefers-reduced-motion.

What is verified and what is not

The skill is explicit about its own evidence, which is the part that makes it safe to hand to someone else. Values carry a status, and the agent is told never to invent a hex code, a font implementation, a DOI or a credit.
